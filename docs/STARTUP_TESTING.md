# 冷热启动测试

实现日期：2026-11-25。测量口径 `startup-v2`，桌面启动协议版本 1。

## 支持范围

| 发起入口 | Android App | iOS App |
| --- | --- | --- |
| 桌面客户端、本机设备 | ADB 冷启动与后台恢复、就绪检查、原轮次 Perfetto、离线分析 | 复用设备 WDA，冷启动与后台恢复、就绪检查、状态和失败截图 |
| Web、服务端设备 | 服务端 Android 采集器 | 服务端实际可达的 WDA 采集器 |
| Web、桌面连接的设备 | 派发到设备登记的在线桌面实例 | 派发到设备登记的在线桌面实例 |

Web 指管理平台的发起入口，被测对象仍是手机 App。浏览器导航、网页缓存、Electron 自身启动性能不属于本专项。

桌面需要先登录平台、同步本机设备。新测试登记需要平台连接；已经开始的测试会保存本地轮次、截图、日志和 Trace。网络断开期间保留已有结果，超过执行租约会停止后续采样；恢复连接后补传已有结果。

iOS 首批运行环境是 macOS、真机和可用 WDA。桌面使用现有 WDA registry、USB 转发和驱动，不创建第二套 WDA 管理器。Windows 上仅在现有工具链和设备 WDA 可达时使用，不提供首次构建或签名 WDA。测试开始前需解锁设备、安装目标 App；Bundle ID 不可指向 WDA Runner。

## 使用步骤

1. 在桌面登录并同步设备，或在 Web 确认设备所属执行节点在线。
2. 打开“专项测试 → 冷热启动”，选择 Android 或 iOS；一次提交只选同平台设备。不可用设备会显示具体原因。
3. 填写 Android 包名或 iOS Bundle ID。Android Activity 可以留空自动解析 Launcher Activity。
4. 选择冷启动、热启动（后台恢复）和每模式轮次。快速检查可以少量采样；正式比较建议每模式至少 20–30 轮。
5. 选择性能阈值对应的指标，分别配置冷启动与后台恢复阈值。业务就绪指标需要开启就绪检查并指定目标页面唯一元素。
6. Android 可按需开启 Perfetto；取证在正式启动前开始，保存超阈值或失败的原轮次，不通过复跑替代原慢样本。
7. 观察任务进度，按需取消；在任务或报告中心打开部分或最终报告。取消后保留已完成轮次。

提交超时后，页面保留原配置和请求编号，“确认提交结果”复用同一次请求。重新进入页面仍能恢复未确认请求。平台和桌面均拒绝同编号不同配置，避免响应丢失造成重复启动。

## 冷热与成功口径

冷启动会先停止目标 App，并确认其不在运行，再开始计时；保留登录、缓存和 App 数据。它不等于首次安装、清数据或重启手机后的启动。

后台恢复会先启动 App、完成准备、回到 Home，再确认 App 仍在后台。Android 优先检查 `LaunchState`，Activity 重建的 WARM/COLD 样本不进入 HOT 统计；缺少可信启动状态时标为未验证。iOS 检查 WDA 状态 2/3，并在可取得 PID 时对比恢复前后的进程；进程回收或重建不会算作热启动。正式计时前再次校验状态，工具初始化、准备和轮次间隔都不计入样本。

报告分别记录：

- **启动成功**：启动/激活操作成功且确认目标 App 在前台。
- **业务就绪成功**：开启检查时，在截止时间内观察到目标 App 前台并命中精确 locator；查询错误和超时不能通过。
- **样本有效性**：实际生命周期状态能证明属于请求的冷启动或后台恢复。
- **性能达标**：有效指标值不超过配置阈值；独立于 Perfetto 是否开启，不改变启动/业务成功结果。

业务就绪查询与启动命令并行，在 `am start -W` 返回前也能观察页面。报告的时间仍包含查询与采样开销，不将人工扣除的延迟伪装成系统指标。

## 指标解释

| 字段 | 平台 | 含义 |
| --- | --- | --- |
| `this_time_ms` / `total_time_ms` / `wait_time_ms` | Android | 原样保留 `am start -W` 的系统返回值；缺失保持 null |
| `automation_ms` | Android | 从主机发起启动至命令返回并确认前台，包含 ADB 与状态查询开销 |
| `automation_ms` | iOS | 从主机发起 WDA launch/activate 至返回并确认前台，包含控制与状态查询开销 |
| `ready_ms` | Android/iOS | 从发起启动/恢复至首次观测到目标 App 前台且指定就绪元素命中 |
| `displayed` / `fully_drawn` | Android、实际有日志时 | 保留对应平台日志及其来源；未采集时留空 |

WDA 耗时不填入 Android TotalTime，也不标为 iOS 系统首帧或 `XCTApplicationLaunchMetric`。iOS 系统级 XCTest 精确指标属于后续增强。

均值、最小/最大、P50/P90/P95 按模式与指标各自的有效正式样本计算。诊断复跑、状态无效、其他平台/测量版本及缺失值不混入；业务就绪超时的原生 Android 指标仍可作为该原生指标的有效采样。少于 20 个样本时提示样本不足。`0 ms` 保留，null 显示“未采集”。

历史 Android 报告维持原解释，不重算旧结果；页面会提示旧口径没有核验真实冷热状态，旧就绪超时可能未影响成功统计。

## 证据与恢复

每轮保存应用状态、实际模式、计时来源、错误与无效原因。失败轮次在设备可用时保存 PNG 截图，Android 日志或 iOS WDA 状态日志单独保存。报告提供截图和日志入口，未同步的证据明确标为待同步。

Android Perfetto 最多保留六份原轮次 Trace。桌面内置固定版本的官方 Trace Processor，首次本地分析不需要运行时下载。分析展示启动区间、主线程切片、CPU 调度与线程状态；缺少启动事件或调度数据时返回部分分析，不编造瓶颈结论。平台已有 Trace/AI 接口仍可继续用于分析与总结。

本地待传文件保存配置、同一 task/run 标识、轮次与证据，不保存登录 token、Cookie 或 claim token。客户端重启后只恢复结果上传，未完成采样进入 ABORTED，不自动续跑计时。重新登录同一平台和账号后才处理其本地待传结果。

设备与用例、场景、Fastbot、录制交互共享互斥控制。取消等待实际 ADB/WDA 调用结束才释放本地设备。云端租约为 90 秒，失联后保留 120 秒安全宽限处理在途清理，再按原任务 owner 释放占用；旧认领不能复活。协议与接口见 [派发与恢复协议](STARTUP_DISPATCH_PROTOCOL.md)。

## 发布与验证

先更新平台并执行 `20261125_042_startup_execution` 迁移，再发布桌面和共享前端。迁移新增客户端能力与启动命令记录，已有 FastbotTask/FastbotReport 继续使用。旧桌面没有启动能力时显示升级提示，设备不会误交给服务端 ADB。

桌面构建会下载并校验固定版本的 macOS Intel/ARM、Windows x64 Trace Processor；打包时嵌入当前平台二进制及许可。`--verify-only` 和引擎 `--check-startup` 用于无网络验包。

自动化验证覆盖计时、业务就绪超时、状态无效、取消、原子占用、账号/实例与 attempt 约束、重复提交/认领、离线结果恢复、迁移、报告、前端能力门控和真实原生 Trace SQL。最新验证证据保存在工作区 `artifacts/startup-20261125/`。

本轮主机查询到的 Android/iOS 真机清单为空，尚未完成手机实测。上线验收仍需真实设备执行 cold/hot、ready 开/关、断线取消与跨 Web/桌面的同报告核对；Windows 与 macOS Intel 的原生运行也需在对应平台验包。自动化测试和 macOS ARM 冻结引擎自检不替代这些实测。
