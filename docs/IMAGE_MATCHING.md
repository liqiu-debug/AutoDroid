# 单模板多设备图像定位与点击

图像点击和存在／不存在断言默认使用 `adaptive-v2`，旧步骤没有新增配置时也自动使用该能力。原图片只保留一份；不同型号和 Android/iOS 共用同一原图及内容 SHA。显式 `image_match.profile="strict-v1"` 继续使用原严格像素规则。

`adaptive-v2` 先以图像金字塔搜索可容纳目标的尺度，粗候选在原像素上按缩放后整数宽高细化位置和尺度。原 NCC、双向轮廓、前景、局部和颜色验收门槛保持不变。`source_size` 作为优先搜索提示，屏幕长宽比变化不再直接拒绝模板；显式 `search_region` 同时限制视觉区域、必需文字及点击点。

包含独立图标及外置标签时，准备服务从同一原图自动生成结构描述。稳定图标继续严格像素验证；外部文字使用同一执行帧的邻域 OCR、Unicode NFC 和空白归一后的精确文本比较及位置关系联合验证。品牌图标内部文字仍属于视觉图案。大小写、数字、标点、标签顺序不被忽略，不使用编辑距离或全屏文字点击替代图像定位。

完整模板与组合匹配的候选最终合并后消歧；同一图标附近多个合格标签保留存在证据但拒绝不确定点击。点击锚点归属到原图的视觉或文字部件，按已验证部件映射，连续两帧稳定后只提交一次点击。模板描述未覆盖必要前景、OCR 低置信／无邻域证据、能力缺失、候选溢出或预算未完成不能证明不存在。

模板分析目前保守支持一个主要视觉块及相邻外部标签。无法可靠解释全部前景的复杂图案保留整图严格验证；不会静默删除图案或标签。内容重绘、严重主题变化或缺少可靠视觉证据仍可能被拒绝。


`strict-v1` 以拒绝不确定目标为默认行为，覆盖平台 Python、Desktop vendor、Android 手机端 OpenCV 和 iOS WDA。它替换 Android 图像点击的 `ImageX.wait`，并移除了图像动作隐式改为全屏确认文字点击和点击后同位补点的行为。

## 使用方式

录制时圈选完整、稳定的图标或文字。图像点击和图像断言的“去截取”均在拖拽结束后自动保存模板；快捷图像点击只需确认一次。界面不再显示红色点击点、坐标或要求手动验证定位。快捷录制保存模板后，直接在用户指定位置提交一次录制点击，不调用步骤回放或全屏匹配，也不等待匹配超时。原点击点相对模板的位置会一并保存；如果调整选区后排除了原点击点，则使用新选区中心并保存对应锚点。手动圈选默认使用中心点，仅保存模板。

两个图像步骤均保留可选的“验证当前设备定位”按钮，读取当前设备截图并展示候选框，不执行点击或断言，也不作为录制保存的前置条件。断言预览遇到多个合格目标时显示图像存在。

回放或单步执行图像点击时重新读取设备截图、确认目标唯一且两帧稳定，再提交一次点击。遇到多个相似目标时给出提示并拒绝点击，已录制的步骤仍然保留。图像断言只判断存在或不存在，不执行点击；多个合格目标仍可通过“存在”断言。纯色、过小或信息不足的模板会被拒绝或提示重新截取。

模板几何元数据仍按平台保存在步骤 JSON 中，共享匹配描述独立于平台配置，已有锚点和显式搜索区域继续生效。桌面端执行图像点击、图像断言时，按当前平台选择模板并解析到用户数据目录的缓存文件；不会将录制模板解析到应用安装目录。下载或缓存读取失败会明确报错，“不存在”断言也不能因此通过。

模板裁剪与“验证当前设备定位”使用原尺寸无损 PNG 截图，WDA 返回的原生 PNG 不再二次转为 JPEG。设备中心的缩放预览和 MJPEG 展示使用独立链路。已有从 JPEG 录制帧裁出的模板继续兼容，无需批量重截。

旧步骤没有额外参数时自动分析同一原图并采用自适应匹配；已有点击锚点继续保留。旧桌面客户端缺少能力声明时，新前端会要求升级。手机端原生能力缺失、OpenCV 无法加载或模板 SHA 不一致时，执行明确失败，不切换到旧算法。

## 数据与接口

标准步骤使用 `args.image_options`，旧步骤使用 `options.image_options`。按 `android`、`ios` 或显式共享的 `default` 保存配置：

```json
{
  "image_path": "static/images/element_example.png",
  "image_options": {
    "android": {
      "template_sha256": "原始模板文件的64位SHA256",
      "tap_anchor": [0.2, 0.5],
      "source_size": [1080, 2400],
      "search_region": [0, 0, 0.5, 1]
    }
  }
}
```

`tap_anchor` 相对于模板；`search_region` 相对于当前截图，缺省全屏。`strict-v1` 仍拒绝截图宽高缩放比不一致超过 3%；`adaptive-v2` 将录制尺寸作为搜索优先提示。坐标在最终原图尺度计算；iOS 仅在发送点击时转换为 WDA 点坐标。配置与原始模板文件 SHA 绑定，避免同路径换图后继续使用旧锚点。

配置选择优先使用当前平台，其次使用 `default`。当前平台未配置、且选用的是另一平台的同一个模板时，只借用模板 SHA 和模板内点击锚点，去掉源设备的 `source_size`、`search_region`，在目标设备全屏使用选定的共享匹配 profile。已有独立模板却缺少绑定元数据的旧步骤使用无配置严格匹配，不附加另一张图的 SHA 或锚点。重截一个平台时保留另一个平台的模板和原绑定；原先两平台共用的旧模板也会保留下来。

共享配置保存于标准 `args.image_match`，旧模型对应 `options.image_match`，不放在平台 `image_options.default`：

```json
{
  "image_match": {
    "profile": "adaptive-v2",
    "template_sha256": "原图片SHA256",
    "descriptor": {"schema_version": 1, "template_size": [277, 122], "regions": [], "relations": [], "tap": {}},
    "descriptor_canonical": "由准备服务生成的排序紧凑JSON原文",
    "descriptor_sha256": "上述UTF-8原文的SHA256"
  }
}
```

上例的空描述仅展示字段形状，实际配置由服务自动生成，所有必要区域均标记 `required=true`。描述绑定原 PNG 和分析版本；脚本导出及本地模板缓存完成后冻结描述，运行端不重新识别模板文字。模板分析缓存按内容 SHA、分析版本、OCR 模型版本及锚点定位，最多保留256条内存记录；进程重启后可重新分析。原图片改变、描述原文／摘要不一致或非法显式配置均明确拒绝。

裁图接口增量返回 `template_sha256`、`source_size`、`quality` 和 `image_match`。`POST /api/device/match_image` 接收 `screenshot_base64`、`image_path`、共享 `image_match` 和已经选定平台的扁平 `image_options`；返回状态、候选框、各项指标、拟点击点、质量与耗时。它不获取设备，也不调用执行器。

Desktop `/api/client/info` 返回 `image_matcher: {version, validated, preview, metadata, profiles, descriptor_versions}`。手机端使用 `images.strictMatcherCapabilities()`，并携带共享验收集指纹，声明支持的 profile 与描述版本。缺少 `adaptive-v2` 能力时默认图像动作明确提示升级，不忽略共享描述。

成功与失败的图像诊断都进入步骤结果 `output.image_match`。错误码：

| 错误码 | 含义 |
|---|---|
| E2005 | 没有通过验证的候选 |
| E2010 | 多个相似目标或证据不足以消歧 |
| E2011 | 模板无效或缺少可识别信息 |
| E2012 | 目标不稳定或超时 |
| E2013 | 当前配置或运行端缺少必要能力 |
| E2201 | 配置无效、模板 SHA 已变化 |

Python 后端及桌面引擎在定位预算耗尽时记录 `timed_out`、`timeout_reason` 和 `frames_checked`。最后一次截图或计算未完成时，仍保留先前完整验证的候选和指标；每帧均未通过的结果保持 `not_found`，曾找到但无法连续两帧稳定的目标才报 `target_not_stable`。截图读取超时、定位计算超时分别给出对应提示。

## 算法和执行约束

归一化去均值相关搜索多个局部候选，在原始像素分辨率验证双向轮廓覆盖率、前景误差、局部块误差和适用时的空间颜色误差。验证后合并同一对象的多尺度候选；多个独立合格目标或最佳候选优势不足时拒绝点击。

轮廓阈值使用 Sobel 强度至少为 8 的有效梯度计算 90 分位，再取其四分之一与 8 的较大值。这样稀疏细线图标的大面积纯色背景不会压低分位数，使 JPEG 压缩噪点被错误当作轮廓。NCC、双向轮廓覆盖率 0.88、前景/局部/颜色误差及消歧门槛保持不变；Python、Desktop、Android、WDA 使用相同规则。

前景复核同时检查 4×4 分块和 16×16 像素重叠窗口（步长 8 像素，至少 8 个前景像素，误差上限 0.22），避免共享按钮边框、长标签掩盖单个数字差异。固定 PNG 回归包含 OpenCV 5 绘制的 `Order 1` / `Order 2`，不依赖测试机器的字体绘制版本；相同文字与轻微 JPEG 差异仍须通过。

参数集中为版本化 profile；不会在重试时降低阈值。两次截图间隔约 150 ms，局部框 IoU 至少 0.9，拟点击点偏移不超过 `max(2px, 模板短边×2%)`，且每帧均须通过完整结构验证。整个步骤的重试和退避共享超时预算。

取消后不得提交点击。Android 使用受 deadline 约束的单次 ADB 隧道 JSON-RPC；iOS 使用单次 WDA HTTP 请求，避免 SDK 自动恢复时重发有副作用的点击。提交结果未知时禁止自动重放步骤。

图像断言复用严格定位，但保持存在性语义：任意合格候选可证明“存在”；“不存在”需要连续两次明确未找到。多个合格目标可通过存在断言。模板无效、能力不足、定位异常或不确定结果均不能证明不存在。

## 验证与发布

生成与执行离线基准：

```sh
.venv/bin/python scripts/maintenance/benchmark_image_match.py generate --directory /tmp/image-calibration --split calibration
.venv/bin/python scripts/maintenance/benchmark_image_match.py generate --directory /tmp/image-acceptance --split acceptance
.venv/bin/python scripts/maintenance/benchmark_image_match.py evaluate --directory /tmp/image-acceptance
```

校准集和验收集使用不同模板家族，各包含 200 正例和 1,000 负例。冻结 profile 在校准集达到零误接受、100% 正例召回，不需要进一步放宽。2026-11-16 的共同验收额外加入 19 个真实模板空白负例、2 个真实搜索错配截图负例和 1 个真实签到正例，共 201 正例、1,021 负例。

平台、Desktop、Android 真实 OpenCV JNI 与 iOS 原生 matcher 在共同集均达到 201 正例正确定位、负例零误接受。生成样本覆盖明确的工程边界，不等于 200 个独立生产页面，也不承诺未来页面零误点。正式发布仍应先灰度观察真实业务模板的拒绝率和耗时；失败时暂停受影响能力，不回退宽松匹配。

本次验证结果和可重放数据位于工作区 `artifacts/image-click-audit-20261116/`。本次仅修改源码和本地验证，未发布桌面更新、安装物理设备 App 或修改线上服务。

## 离线打包自检

Desktop 支持 `autodroid-engine --check-image-match <fixtures_dir>`。目录提供 `156-template.png`、`156-screen.png`、`161-template.png`、`161-screen.png`；自检使用真实生产分析器、156双帧定位和161存在断言，只读文件，不连接设备或点击。成功输出 `ok=true` 的 JSON，匹配失败返回1，参数错误返回2。冻结包验收必须实际运行该入口。

本次新增验收覆盖中间尺度、超出旧范围的缩放、组合错字／邻行、重复标签、描述篡改、搜索区域越界、无 OCR 证据和预算耗尽。历史156/161截图为诊断资产，测试通过环境变量提供，未保存进产品代码。Android原生视觉代码的桌面JNI验收与真实Android/MLKit设备验收分别记录，不能相互替代。
