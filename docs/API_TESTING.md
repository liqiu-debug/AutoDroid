# 接口自动化

接口自动化独立于 Android/iOS 设备执行，通过“添加请求 → 查看响应 → 点选字段取值与校验 → 运行场景 → 定位失败”完成低代码自动化。支持 HTTP(S)、JSON/普通表单/文本请求、顺序场景、字段引用、校验、调试、报告、定时执行和飞书通知；接口可从 cURL、OpenAPI、Swagger 或 Postman 文档录入；AI 为可选辅助。

## 首次配置

1. 按现有部署流程安装基础依赖、构建前端并重启后端。数据库启动时自动创建接口自动化表并执行幂等迁移；升级前照常备份数据库。
2. 在「测试资产 → 全局变量库」创建环境及服务地址、账号、密钥变量。`is_secret` 沿用全局变量库的展示标记，不代表数据库加密；接口自动化的请求、响应和报告按实际值展示。
3. 如需飞书通知，在「系统配置 → 系统设置 → 通知推送 → 接口自动化报告」填写独立 Webhook（`api_testing_webhook`），并配置共用的**系统访问地址**。系统地址必须能从飞书用户的浏览器访问；报告链接仍要求登录。旧的 UI 场景 Webhook 不会自动作为接口通知地址，需要显式填写。
4. 如需 AI，在「系统配置 → 系统设置 → AI 模型」配置 API Key、Base URL 和模型名称，开启「接口自动化 AI 辅助」并保存。开关 `api_testing_ai_enabled` 默认关闭；关闭或缺少有效配置时不显示可用 AI 入口，手工配置和执行仍可完整使用。

按团队内部使用要求，不配置域名白名单，不限制目标 IP 范围；后端能访问的公网、内网及本机 HTTP/HTTPS 接口均可测试。原 `api_testing_allowed_hosts` 设置不再使用，`/policy` 端点已移除。TLS 验证始终开启；不跟随重定向、不读取代理环境变量、不自动重试。

## 录入与调试接口

- 「接口管理」提供目录、表单编辑、复制、搜索、删除、cURL 导入和接口文档导入。
- 接口编辑页的“加入场景”会先保存接口，再选择新建或已有场景；跳转后只加入场景草稿，保存场景才生效。
- cURL 导入只解析，不启动 shell。支持常见请求方法、请求头、Cookie、Basic、JSON、普通表单；文件参数、命令替换、多个 URL、重定向及未支持的选项会明确拒绝。
- **接口文档导入**（「接口管理 → 导入文档」，或场景「添加步骤 → 导入接口文档」）支持 OpenAPI 3、Swagger 2.0 和 Postman v2.1，JSON 与 YAML 均可。同样只解析不发送请求：先粘贴内容点“解析预览”，再勾选需要的接口，最后选目标目录导入。只创建勾选项，未勾选的不会进入接口库。解析按接口列出提示，逐项说明需要人工确认的地方：服务地址取自文档、建议改为 `{{BASE_URL}}`；路径参数需要在场景中填写后才能调试；鉴权方式需要在「鉴权」中配置凭证或敏感环境变量；文件上传、不支持的内容类型和方法会被跳过并说明。路径参数保留 `{id}` 占位并自动生成同名路径参数；JSON 请求体按文档结构生成可编辑的示例（优先取文档中的 example），响应示例（OpenAPI 的 2xx 示例、Postman 保存的响应）会一并存为样例，导入后无需先调试即可选取字段。**Postman 集合里声明的凭证不会作为值导入**（Bearer/Basic/API Key 只映射类型，凭证留空），请求头中的凭证按原文保留但会提示替换为敏感环境变量；导入不读取本地文件、不访问网络，YAML 使用安全解析，不接受任意对象构造。单次上限 2 MiB、300 个接口。
- 列表和编辑器显示创建人、创建时间、最后修改人和时间、所属目录及团队共享信息。旧记录无法还原的修改人显示 `-`；新修改会记录实际操作者，创建人不随修改改变。
- URL 支持现有 `{{BASE_URL}}` 环境变量写法；路径占位符如 `{id}` 由路径参数替换并编码。接口定义只提供“环境变量”和“拼接变量”入口，前序步骤引用仅在场景中提供。
- JSON 请求体默认直接编辑 JSON，支持粘贴、格式化及错误提示。无效 JSON 阻止保存和调试。需要绑定时切换“字段与变量”（接口）或“字段与引用”（场景）；已绑定的值不会被转为普通 JSON，避免丢失引用。数字、布尔、空值、对象和数组保留原类型。
- 鉴权支持 Bearer、Basic、API Key；Cookie 可手工填写，请求内自动管理的 Cookie 仅在同一次场景/调试会话中共享。
- **请求头以配置为准**。`Host`、`Content-Length`、`Connection` 这类通常由执行器推导的请求头，只在请求没有配置时才由执行器补上；配置页面写了就按配置发送（例如用自定义 `Host` 测试虚拟主机），预检不再提示“由执行器管理”。`Transfer-Encoding: chunked` 会让执行器按分块编码发送并省略 `Content-Length`；传输层无法按配置发送的组合（`Content-Length` 与请求体长度不符、`Transfer-Encoding` 取 chunked 以外的值）在执行时记为**配置错误**并明确说明，不会变成含混的内部异常。
- 保存的响应样例只用于提供字段树，不参与运行。接口暂不可达时，可粘贴响应体 JSON 后保存。

**调试是真实请求，不是模拟执行。创建、修改和删除操作会产生真实业务数据。系统不做业务回滚，也不自动重试。**

## 编排场景

进入「接口自动化 → 自动化场景」，空白页及“添加步骤”提供四个入口，不要求先维护公共接口：

- **新建请求**：直接创建场景内请求，填写方法、地址、参数并调试。
- **粘贴 cURL**：解析后加入场景草稿，不立即发送请求。
- **导入接口文档**：解析 OpenAPI/Swagger/Postman 文档，勾选后先在接口库创建接口，再加入当前场景草稿。
- **从接口库选择**：按目录搜索并批量加入公共接口。

编辑器采用左侧步骤列表、右侧请求配置与响应的布局。步骤卡片只显示请求方法与校验数（如 `POST · 2 条校验`），卡片较窄，不展示地址。场景说明常驻在标题下方，为空时提示补充，点击即可打开“场景信息”；说明随运行一起冻结，报告头也会显示，接手者不必打开场景就能知道这次运行的目的。
调试工具栏固定在配置与响应之间，响应区高度可调整；名称和默认环境位于顶部，说明、目录和资产信息在“更多 → 场景信息”。

顶部**默认环境**随场景保存，正常情况下调试和运行使用该环境。“更多 → 仅本次运行设置”可开启临时环境覆盖，页面显示“仅本次”标签；临时选择只影响当前编辑会话的调试与运行，不改变保存的默认环境。切换环境需重新调试。接口编辑页的环境仅用于该接口调试，不保存为公共接口默认环境；定时任务使用自身保存的环境。

按顺序执行；同一接口可多次添加，步骤 ID 独立。支持等待步骤（0–300 秒）、复制、拖动排序和局部覆盖。错误引用会指出具体步骤和输入位置，可点击定位。

场景内请求可独立保存，无需关联公共接口。步骤菜单的“另存到接口库”创建独立副本；需在另存弹窗中把前序步骤引用替换为环境变量或固定输入，全部处理后才能保存。原场景及引用不变，另存不会自动把原步骤改为库关联步骤。

从接口库加入的步骤保存模板快照。修改公共接口不会改变已有场景；“接口有更新”可查看差异，冲突项显式选择保留覆盖或采用新模板，再保存场景。请求体的局部覆盖按整个请求体保存，不会深层合并恢复已删除字段。

**接口变更的影响面与批量同步**：接口编辑页顶部显示“被 N 个场景的 M 个步骤引用”，可展开查看每个引用步骤的状态（已是最新 / 待同步 / 需逐项确认）并跳转到对应场景定位该步骤；场景列表在名称旁显示“接口有更新”角标，不必逐个打开场景才发现需要同步。没有本步骤修改的旧版本步骤可以在接口编辑页一键“同步 N 个步骤”，一次更新到当前接口配置；**有本步骤修改的字段不会被静默覆盖**，这类步骤标记为“需逐项确认”，仍需进入场景用逐项选择处理。同步按步骤独立处理，某个场景版本已被他人修改、或正在运行时，只跳过该项并说明原因，其余步骤照常更新。成功同步会提升场景版本号，因此同时打开的编辑器保存时会得到并发冲突提示，而不是覆盖同步结果。

引用方式：值旁“取值” → 前序步骤输出 → 选择字段。字段树显示当前字段名、简短示例值及来源，选中后可查看完整路径和复制完整示例；状态码、响应头、Cookie、正文等入口始终保留。引用标签可重新选择或跳转来源步骤。内部保存步骤 ID 和路径片段，用户不需要输入表达式。

JSON 的完整引用保留原类型；文本位置只接受标量，可在同一输入区域插入文字和引用。对象、数组在文本位置会禁用并说明原因。JSON 请求预览显示运行时取值标记，不把引用转为固定值。支持数组固定下标，不支持通配符、条件筛选或脚本。缺失字段和越界下标会报错，`null`、`false` 和 `0` 不被当作不存在。

- **调试本步**：只执行该步骤，需要已有有效的前序真实结果。
- **从头执行到此步**：明确列出将执行的步骤，用新上下文运行这一段。
- **重新校验响应**：使用本会话的有效真实响应重新判断当前规则，不发送 HTTP 请求。前序步骤待校验、未校验或失败时，先处理前序步骤再向后调试。
- **运行场景 / 保存并运行**：先完成正式运行预检；草稿有修改时先保存，保存失败不启动。每次使用新的上下文，永不使用样例或旧调试值；临时环境覆盖优先于场景默认环境。

修改步骤名称、说明保留请求结果；修改断言保留响应并标记“断言待校验”。修改请求、鉴权或环境会使当前及下游执行结果失效，但保留历史展示。调试预检只检查到当前步骤，不被未完成的后续配置阻塞。未启用的参数、未使用的请求体及鉴权字段不参与预检。

预检区分三个层次：**保存**校验数据结构、步骤 ID 和引用顺序，允许尚未填写完整请求或未添加校验的草稿；**调试**检查将执行的请求地址、有效参数、鉴权、环境变量及引用；**正式运行**再要求场景至少包含一个请求、每个请求至少一条校验。接口返回具体步骤、输入位置、所属面板和错误类别，页面可点击定位。HTTP 请求方法、JSON 等基础数据类型始终受 schema 校验约束，保存草稿不意味着允许任意无效结构。

保存场景时会保留已调试步骤的响应字段结构、示例和来源时间，重新打开仍可选取嵌套字段及数组下标。保存的结构、接口样例和历史展示只供配置参考，绝不恢复执行上下文。删除步骤同时清理其展示历史。环境或编辑器实例变化时创建新会话。调试会话按用户隔离，空闲 30 分钟过期，清理任务每分钟回收。关闭编辑器会中止并清理该调试会话。

环境选择旁的“环境变量”抽屉可查看和维护变量，新建环境或修改变量会清理旧调试上下文。登录响应中选择 token 后点“用于鉴权”，可批量应用到指定后续步骤的 Bearer 或自定义请求头；已有配置逐项确认保留或替换。

断言的“选择响应字段”可展开对象和数组下标；粘贴响应 JSON 样例后无需先保存即可选取嵌套字段。尚无响应或样例时仅提供标准外层字段，并提示先调试或添加样例。

## 断言、报告和通知

按团队使用要求，接口自动化中的 Cookie、AT/token、鉴权头和其他字段在调试、响应样例、字段示例、报告及 HTML 导出中明文展示，包括从敏感环境变量解析出的实际值。旧 `sensitive_paths` 配置保留兼容但不再脱敏，编辑器不再提供该设置。已保存为 `••••••` 的旧样例和历史报告无法还原，需要重新录入样例或执行。全局变量库及 UI 自动化的原有展示行为不变。

校验使用“字段 + 条件 + 期望值”，期望值支持环境变量和前序输出。响应字段旁可直接添加校验：普通字段从本次真实响应带入等值建议，从历史或样例新增时留空供确认；识别为 ID、token、时间等动态字段时默认选择“非空”，避免固定单次随机值。**手动把动态字段改成“等于”时会在该行就地提示**“该字段每次运行通常不同，固定值容易误报”，并提供一键改为“非空”或“与前序字段一致”，不阻断保存——初级测试最常见的误报来源是写死订单号、时间戳这类每次都会变的值。条件随字段类型筛选，类型检查用中文下拉选项，长度检查用数字输入。新请求初始化一次状态码 2xx 校验，新增业务校验不会重复添加；负向测试可改为预期 400 等状态。

**零条校验的调试结果为 `UNCHECKED`（未校验），不计为通过，也不能给后续步骤提供已验证输出。** 可以先发送请求查看响应，再补规则并点击“重新校验响应”。同一步所有校验通过才进入 `PASS`；失败、异常或未校验会停止顺序执行，后续步骤跳过。正式运行的零校验请求会在发请求前被阻止。旧报告中曾被记为通过的零校验请求保留历史状态，同时注明“当时仅表示请求完成”。

默认总请求超时 30 秒（可调至 120 秒），响应解压后上限 5 MiB，超限失败，不解析截断 JSON。响应字段树最多展示 2000 节点、32 层，展示限制不改变运行时数据。

**失败重试（步骤「高级 → 失败重试」，0–3 次，默认 0）** 只重试**请求根本没有到达服务端**的情况：连接被拒绝、连接超时、代理错误。已收到响应（无论断言是否通过）、读超时、写超时一律不重试。理由是本模块不做业务回滚：接口步骤可能是 `POST /orders`，而读超时意味着服务端可能已经处理完并产生了数据，重复发送等于重复写入业务数据。这一点与 UI 用例的失败重试语义**有意不同**——界面操作是幂等的，接口写入不是。重试间隔 1 秒，中止时立即停止。结果记录实际尝试次数，报告和响应区在尝试次数大于 1 时标注“共尝试 N 次”并列出前几次的连接失败原因，避免“靠重试通过”被当成稳定通过。

报告中心的「接口自动化」页签展示运行记录；「运行概览」大盘有独立的「接口自动化」板块（执行次数、通过率、失败、运行中、平均耗时、趋势与最近运行），跟随大盘的时间范围，不受平台筛选影响，也不并入设备执行的 KPI。报告区分配置错误、连接异常、HTTP 问题和校验失败，展示失败步骤、字段路径、期望和实际值，默认展开失败位置。响应正文与请求头、Cookie、原始文本分开展示，引用来源显示冻结的步骤名称和本次实际值。可返回场景定位对应步骤；历史报告保持当次配置。详情包含环境、执行人、耗时，以及**独立的飞书通知状态**。支持认证后下载自包含、无脚本 HTML。保留天数沿用 `report_retention_days`，0 表示不清理。

手动运行可勾选飞书通知；定时任务沿用原通知开关。两者均使用接口自动化独立的 Webhook，不回退到 UI 场景的地址。卡片仅包含场景、环境、结果、步骤统计、耗时及报告链接，不发送请求/响应/凭证。未配置接口 Webhook 显示“未发送”，发送失败记录原因，但不改变测试结果。服务重启中断的运行记为异常，未完成通知记为失败，不自动续跑或重发。

飞书测试消息与各类报告通知直接连接 Webhook，不读取进程的代理环境变量，避免 `NO_PROXY` 中 IPv6 项导致 `Invalid port: ':1'` 初始化失败；TLS 验证仍开启。

在「定时任务」中选择“接口自动化”、接口场景、环境与执行策略，无需设备。也可从场景编辑器“更多 → 定时与通知”打开预填抽屉，查看已有任务、下次执行时间和通知配置，支持新增、编辑和启停。上次任务未完成时跳过重复触发并记录日志；预检失败也生成异常报告。

## 可选 AI 辅助

AI 复用既有 `ai_api_key`、`ai_api_base`、`ai_model` 和 OpenAI 兼容协议，仅提供两个按需入口：

- **AI 校验建议**：在接口或场景的真实响应区打开，填写可选业务目标，查看建议及依据，勾选后加入校验草稿。样例不能替代真实响应；当前 `UNCHECKED` 响应可用于补规则，前序步骤必须通过。未知路径、错误类型、固定 ID/token/时间值等建议会被过滤并说明原因；无业务目标时，不建议固定正文业务值。应用后可重新校验响应，不重复发业务请求。
- **AI 解释失败**：在已完成的失败报告打开，区分服务端生成的已知事实、模型提出的可能原因和下一步排查。事实显示字段路径，解释只能引用存在的事实 ID，可跳转对应步骤；不改变报告结果，也不自动修复或重跑。
- **建议数量与去重**：一次生成默认**最多 6 条**，填写了业务目标时放宽到 8 条。服务端把同一字段的「存在 / 非空 / 类型为」合并为一条（数字、布尔取「类型为」，字符串、数组、对象取「非空」），再按价值排序后截断：被后续步骤引用的字段 > 业务结果字段（code / success / status / message 等）> 状态码 > 浅层字段优先于深层叶子，被截掉的数量会在提示里说明。已存在于当前步骤的校验（相同字段、条件、期望值，或该字段已有结构性校验）不再列出，只提示"N 条建议已存在"；前端应用时再做一次同样的去重，并把已应用的建议置灰标记——因此重复点击"应用"不会累加，重新生成会给出新列表而不覆盖手工修改。
- **AI 批量生成校验**：场景编辑器「更多 → AI 校验建议（全部步骤）」。确认后会**从头真实执行全部步骤**（写入会产生业务数据，不会回滚），再为每个拿到真实响应的步骤生成建议，在一个面板里按步骤分组审阅（默认全选，可逐条取消或整步取消全选），应用后自动按顺序「重新校验响应」——不重发请求。失败步骤不会生成建议（避免把错误响应固化成校验），它之后的步骤标注「未执行：前序步骤未通过」，修好该步后重新执行即可。接口库不提供批量入口：库里的接口大多依赖前序 token 或路径参数，独立执行会大面积失败且可能产生写入数据，单个接口仍用「发送请求 → AI 校验建议」。

批量流程有一个必须遵守的顺序：**先为所有步骤生成、再统一应用、最后逐步重新校验**。给第 N-1 步应用新断言后，服务端会拒绝为第 N 步生成（前序断言已变且未复核），因此界面不会边生成边应用。单步入口保留，因为接口编辑页没有场景、单步用的是已有响应（不重跑），并且只有单步提供「业务目标」输入——服务端在没有目标时会过滤掉固定业务值，这也是获得业务值校验的唯一途径。

请求配置、响应、环境或业务目标改变后，旧校验建议不可应用。生成、应用和解释均防止重复点击；切换报告或关闭编辑器后，旧异步结果不会覆盖新内容。撤销只移除原来加入且未被用户修改的建议，保留其他后续编辑；已修改建议需手动调整。

AI 出站使用单独的上下文白名单：建议发送有限字段路径、类型、HTTP 状态码及清洗后的目标文本；解释发送确定性事实及错误类别。字段名的排除只按敏感**名称**和足够长的密钥值判定：一到三个字符的已登记值（例如某处出现的 `id`）不再让 `user_id` 这类正常字段名被整体剔除，正文清洗仍使用全部已登记值。不发送业务 URL、完整正文值、请求头、Cookie 或原始服务器错误文本。敏感字段及常见个人信息字段会排除，已知密钥、敏感变量值和常见邮箱/手机号等模式会在允许的文本中替换。字段名和用户主动输入的业务目标仍属于模型可见上下文；这不是任意业务文本的完美匿名化，也不改变本地报告的明文展示。

优先请求 JSON Schema 结构化输出，只有服务商明确表示不支持该参数时，才退为提示词约束 JSON，并继续执行服务端严格校验。格式错误、拒答、截断、无效引用不会变成执行脚本或虚构成功模板。AI 关闭/缺配置返回 503，服务或格式异常返回 502，超时返回 504；原草稿及手工流程保持可用。AI 使用独立超时，不读取代理环境变量，不跟随重定向。

调用日志记录调用 ID、用户、模型、提示词版本、净化输入摘要 hash、状态、用量和耗时，不记录原始请求/响应。采纳、修改、关闭和撤销反馈记录所选/修改数量，调用 ID 按用户绑定；重复反馈在前端去重。调用归属及反馈保留在进程内短期缓存中（30 分钟），不构成持久化分析报表。模型只辅助编辑和解释，执行与通过/失败判定继续由现有引擎负责。

## 实现与接口

所有新端点位于认证前缀 `/api/api-testing`，没有未认证的 legacy 别名；开发代理保留该前缀。

| 资源 | 作用 |
|---|---|
| `/interfaces`、`/folders`、`/scenarios` | 接口、目录及场景 CRUD；场景内请求允许 `interface_id` 为空 |
| `/imports/curl` | 只读解析请求 |
| `/imports/spec` | 只读解析 OpenAPI 3 / Swagger 2.0 / Postman v2.1 文档，返回候选、提示和可编辑草稿 |
| `/imports/apply` | 一次事务创建勾选的接口，全建或全不建 |
| `/interfaces/{id}/sync-preview` | 比较模板与覆盖，不自动保存 |
| `/interfaces/{id}/usages` | 该接口被哪些场景的哪些步骤引用，以及每个步骤的过期状态与冲突字段 |
| `/interfaces/{id}/sync-apply` | 批量同步无冲突的步骤；每项独立事务，冲突项需显式选择后才写入 |
| `/precheck` | `validation_mode: debug/run`，返回含 `step_id/location/section/error_category/message` 的问题；保存端点使用保存级校验 |
| `/debug-sessions`、`/debug-sessions/{id}/execute` | 创建隔离会话及异步调试 |
| `/debug-sessions/{id}/assertions` | 对本会话内有效真实响应重新校验，不发送请求 |
| `/scenarios/{id}/schedules`、`/notification-status` | 场景关联任务及通知是否已配置 |
| `/scenarios/{id}/runs` | 运行已保存场景，返回 202 与运行 ID |
| `/runs`、`/runs/{id}`、`/runs/{id}/cancel`、`/runs/{id}/download` | 列表、进度、取消与 HTML 导出 |
| `GET /ai/status` | `enabled/configured/available/reason`，不返回密钥 |
| `POST /ai/suggest-assertions` | 草稿步骤、调试会话、环境、当前步骤、目标和 `draft_token` → 建议、依据、过滤提示、`call_id`、原 token、用量和耗时 |
| `POST /ai/explain-failure` | `run_id` → `facts/possible_causes/next_steps`、证据 ID、调用统计 |
| `POST /ai/feedback` | `call_id`、`action: accepted/modified/dismissed/undone`、`selected_count/modified_count`；不保存场景 |

接口和场景更新必须携带 `version`，并发修改返回 409。场景保存会校验引用顺序。删除仅创建人或管理员可操作；取消仅执行人或管理员可操作。依赖中的接口、场景、环境会阻止删除并显示引用对象。

目前为单后端进程，最多 4 个并发执行工作线程，其余排队；调试上下文和 AI 调用缓存不跨进程共享。继续使用单进程部署，不为该模块单独增加多个 Uvicorn worker。后端网络应能访问测试目标；启用 AI 时还需能访问配置的模型服务。

## 验证

```bash
.venv/bin/python -m unittest backend.tests.test_api_testing_values backend.tests.test_api_testing_engine backend.tests.test_api_testing_api backend.tests.test_api_testing_ai backend.tests.test_api_testing_specs -v
cd frontend
node --test tests/*.test.mjs
npm run build
```

前端测试已接入 CI（`.github/workflows/ci.yml` 的 frontend job 在 `npm ci` 后先跑 `node --test tests/*.test.mjs` 再构建），本地无需记得单独运行即可获得回归保护。

AI 后端测试使用 mock 检查禁用配置、脱敏、用户隔离、过期响应、非法输出、错误/超时及结构化回退；前端使用真实 Vue 响应式验证旧草稿、异步竞态、重复点击、撤销保护和反馈计数。这些测试不代表真实模型联调或模型建议质量验收。

构建前端后，在项目根目录启动隔离浏览器演示（不访问真实接口、不发送飞书、不连接手机、不调用真实模型）：

```bash
API_PREVIEW_DIR=$(mktemp -d /tmp/autodroid-api-preview.XXXXXX)
AUTODROID_API_PREVIEW=1 AUTODROID_API_PREVIEW_AI=1 \
AUTODROID_DB_PATH="$API_PREVIEW_DIR/preview.db" \
  .venv/bin/python -m uvicorn backend.tests.api_testing_preview_app:app --host 127.0.0.1 --port 18765
```

访问 `http://127.0.0.1:18765/api-testing/scenarios`，账号 `preview`、密码 `preview-only`。预览自带两个场景，业务请求仅使用内存 HTTP mock：

- **下单回归 · 示例**（登录 → 创建订单 → 查询订单）：完整链路与跨步骤引用；其中“查询订单”步骤自己改过 `query`，用于验证“需逐项确认”。
- **订单查询 · 轻量示例**（查询订单 + 不稳定接口）：“查询订单”步骤没有本步骤修改，可直接在接口页批量同步；“不稳定接口”重试次数为 1，首次连接失败后重试成功。

“查询订单”接口刻意比场景快照高一个版本，因此列表会显示“接口有更新”，接口页显示引用情况——影响面、批量同步、冲突确认和失败重试都可以在预览里直接验证。`/flaky` 只在进程内第一次调用时模拟连接失败，重启预览后重新可用。

`AUTODROID_API_PREVIEW_AI=1` 只向该临时数据库写入假模型配置、开启 AI，并添加 `preview-ai-failure` 失败报告。AI 请求无条件替换为确定性 mock，即使手工修改预览的供应商配置也不访问真实模型。建议 mock 包含合法建议及应被过滤的动态 ID 建议，失败解释引用真实事实 ID。省略该变量时默认关闭预览 AI。预览要求数据库位于系统临时目录，并校验实际数据库连接一致，不操作正常数据库。

仅限本地验收，**不要将预览应用部署为生产服务**；正式功能仍使用常规 `backend.main:app`。
